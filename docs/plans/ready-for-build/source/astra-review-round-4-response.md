# Response to Astra review, round 4

Claude's resolution of R4-1 to R4-6 in `astra-review-round-4.md`. Each finding was checked against the cited code and plan lines before the edit. All six hold, so each design was rewritten in place in sections 05, 07, 08 and 10. R4-7's two graph edges are applied separately in `tools/graph.json`.

| Finding | Verdict | Resolution | Tickets changed |
|---|---|---|---|
| R4-1 interrupted snapshot not restart-safe | Accept | Recovery builds its work list from durable state on every start and as the sweep's first step: baseline pins whose execution's checkpoint is `interrupted`, has an assistant row and has no snapshot row. It never reads `reconcileOnStartup`'s return value. The insert is conditional (`message_id` is not unique), the baseline pin is deleted only after the snapshot pin exists, and the sweep keeps any baseline still on the work list. The worker-loss coordinator's `onRecovered` runs the same step. | S10-12 |
| R4-2 expiry silently truncates a logical turn | Accept | The range lists a turn's attempts from `canonical_agent_turns`, not snapshot rows. A finished attempt with an assistant row and no snapshot row makes the turn incomplete, and an incomplete turn reads as expired everywhere (`snapshot-expired`, `snapshot_missing`, omitted from `listByThread`). This is simpler than expiring attempts as a unit, which would still miss a snapshot that was never written. | S10-03, S08-03 |
| R4-3 range Revert file loses a renamed file (blocker) | Accept | Every revert scope is rename-closed: the closure of the seed paths over rename links from the attributed groups and from `git diff --name-status -M --diff-filter=R` over the range. It is computed before classification, the preview token and raw capture. Single-turn revert shared the bug: a git-fallback `files_changed` lists a rename by its new name only (`snapshot-service.ts:263`, checked on git 2.41), so Revert this turn deleted `c` without restoring `a`. | S08-03, S10-10 |
| R4-4 steer delivery ownership | Accept | Each steer is a `turn_steers` row written before the adapter call, with states `pending`, `delivered`, `rejected`, `delivery_unknown` and `closed`. A lost or missing answer becomes Delivery unknown with Send again and Remove (decision P8), and the dispatcher never drains such an item. The text survives a reload through `agent.listUnknownSteers`. Codex `clientUserMessageId` and Claude `SDKUserMessage.uuid` carry the id, but neither is relied on to deduplicate. | S05-10 |
| R4-5 shared Implement algorithm still creates a branch | Accept | Step 5 now passes `branchless: true` and `worktreeStart: { commit }` and creates a detached worktree. Step 7 compensation removes the checkout and no branch. The locked decision (line 56) and the `plan.implement` contract row, which still listed "a taken branch name", say the same. | S07-08b (shared steps in S07-07's algorithm) |
| R4-6 Since you looked has two filters | Accept | Backend §2 now selects whole turns: a turn is in when its latest attempt's sequence is past the baseline, and then its whole S10-03 range is in. S08-08 uses that one rule for the diff and for availability. New tests: the user looks between a failed attempt and its Retry, and a variant where the replacement edits nothing. | S08-08 |
