# Implementation notes from the screen pass (scratch)

Findings collected while designing screens on the Paper WIP page. Each item says what the design needs that the code does not do today, or a bug found along the way. Turn this into docs on main once the pass is done. The screen-by-screen decisions live in `screen-pass-todo.md`.

## Shell and sidebar

- Sidebar default width is 304 (Paper `--container-sidebar`), resizable 220 to 340. DESIGN.md still says 256; Paper is the source of truth.
- No title bar: the Windows/Linux caption overlay is 48px high; read its width from `env(titlebar-area-width)`, don't hard-code 146px. macOS traffic lights move to y=18 and hide in full screen.
- Truncation is a 24px right-edge fade everywhere, never an ellipsis.
- Sidebar row states: active turn fades to ~55% with a spinner and no text. A thread that needs the user is never faded: full brightness, amber ring, and a visible label ("Approval required", "Answers required", "Plan ready"). Today only permission requests mark a row (`ThreadStateMarker.tsx:63`), and the label is screen-reader only.
- Finished, not yet opened: filled 8px green dot in the status lane and a green third line "Finished" (no file count), the same shape as the amber "Approval required" row but without the selected fill, so needs-you still outranks done. Both clear when the thread is opened.
- Turn-finished desktop notification is new: Electron `Notification` is only used today for server recovery (`recovery/notifications.ts`) and updates. Fire it only when notifications are on and the window is not focused; clicking it opens the thread.
- Footer: notifications bell (inbox is new; today only toasts) and an update button with rest, checking, up to date, available, downloading, ready, install dialog, failed and nightly states. New: rest-state button, "Up to date" flash, user-facing auto-download setting, install-while-agents-run dialog, "When they finish".

## Turns that don't finish (08f)

- Outcomes already exist: `TurnOutcomeSchema` = completed, cancelled, interrupted, errored (`contracts/models/turn-outcome.ts`). Today the only UI is a footer label in `TurnFooter.tsx` ("You stopped", "Turn interrupted", "Turn failed"): no cause, no next step. The `Error` agent event carries only `error: string`; `Ended` carries `outcome` and an optional `reason`.
- Design: the work fold names the ending ("Stopped after 48s", "Interrupted after 30s", "Failed after 1m 02s"). Any partial answer and the changes bar stay. One end notice closes the turn above the composer: icon, cause (title), detail, one primary action. Map the outcome to a notice in one table, not scattered conditionals.
  - cancelled: quiet line "You stopped", no fill, no button. Edits stay; Revert this turn lives in the turn ⋯ menu.
  - interrupted: amber pause icon, "Interrupted · Mcode closed while Codex was working", Resume (same session when the provider can resume, else a new session seeded with the thread).
  - errored, retryable: clay icon, plain-language cause + status ("Codex stopped responding · 502 Bad Gateway after 3 retries"), Details (expands the raw error in mono with Copy, in place) and Retry (same prompt as a new turn; the agent sees partial edits).
  - errored, usage limit: amber clock, "Claude usage limit reached · 5-hour limit, resets 16:00", Switch model and "Retry at 16:00" (scheduled, not immediate). Uses `RateLimited.retryAfterMs` / `limitType`.
  - errored, signed out: "Cursor is signed out", Sign in, which then becomes Retry. Same action as the bell Providers row.
- Needs an error kind on the wire. Today the error is a bare string, so the UI cannot tell retryable from usage limit from auth. Add `kind` (retryable | usage_limit | auth | fatal) plus optional `status`, `retryAfterMs`, `provider`, classified in each adapter (provider quirks stay at the adapter boundary).
- Retry and Resume are new commands; nothing in contracts re-runs a turn today.
- Sidebar: interrupted gets the amber ring and an amber "Interrupted" line (needs you); failed gets a clay dot and a clay "Failed" line; stopped shows nothing. All clear on open. `ThreadStateMarker.tsx` already has errored and interrupted kinds; rename the visible "Errored" to "Failed" everywhere, toasts included.
  - cancelled before the provider started (no provider frame yet): no work fold, nothing to revert. The user bubble stays with a quiet "Stopped before Codex started" line. No action (user, 2026-10-07). Needs the turn to know whether the provider ever started (first provider frame), which the 04 steps trail already tracks for startup.
  - provider retrying, still running (`ApiRetry`): quiet line under the work, spinner, "Codex is retrying · 502 Bad Gateway · attempt 2 of 10 · next in 8s". No action, no red. Clears when output resumes; becomes Failed if retries run out.
