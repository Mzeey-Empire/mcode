How one provider change becomes a Review you can trust.

The verifier follows a real turn from a provider through server storage to web and Electron. It records evidence when that path works and records a coverage gap when it cannot prove it.

The path under test

Each box answers a different question. A diff must survive every box before the product can claim that the Review panel shows an agent-attributed change.

The same-file check

The hard case is two writers touching the same file. The Review patch must name only the agent change, while the file on disk keeps both changes.

1. Start a marked file

BASELINE_MARKER is written in the verifier-owned fixture workspace.

2. Ask Codex to patch and hold

The prompt requests apply_patch, then holds the turn so the live comparison can appear.

3. Read Live Review first

The verifier waits for the exact file and AGENT_MARKER in the public turn comparison before it permits an external edit.

4. Add an external change

EXTERNAL_MARKER goes to the same file after the live agent patch exists.

5. Compare two views

Review must show the agent marker alone. Disk must retain both markers.

Expected evidence
Review patch + AGENT_MARKER File on disk BASELINE_MARKER + AGENT_MARKER + EXTERNAL_MARKER

This separates agent attribution from a later user change.

What must remain true after the turn ends

LiveStop is visible. The exact file, patch, source, and fidelity are present.
SettledOne row remains. No spinner remains. The public patch still matches the file.
ReconnectClose, reopen, reload, and Electron reconnect keep the same settled evidence.
