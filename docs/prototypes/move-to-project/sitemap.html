Agent and cleanup

Behind the screens.
  • Next turnFresh provider session with a handoff from the thread's saved messages. The earlier-files note rides along once. While another thread uses the folder, the note says to copy and leave the originals.open ›
  • Old folderKept while any No project thread uses it. Mcode deletes it, with its hidden workspace, 7 days after the last one leaves.expired ›
  • New projectThe hidden workspace becomes the project, so the folder is not cleaned up.

Decided

  1. Both destinations ship in v1: an existing project, or a new project made from the folder.
  2. Mcode copies no files into an existing project. The next turn's handoff tells the agent where the old folder is. The note is enough.
  3. The user picks how the thread runs in an existing project during the move: Local, New worktree or Existing worktree.
  4. A new project is not a git repo unless the user ticks Start a git repo.
  5. For a new project, the hidden workspace becomes the project.
  6. Into an existing project only the chosen thread moves. The folder stays while another thread uses it, and Mcode deletes it 7 days after the last one leaves. A new project takes the folder, so every thread in it comes along.
  7. The move waits while the thread is Running or needs approval. A new project also waits for the other threads in the folder.
  8. In the Projects view, dragging a No project row onto a project opens the Move dialog with that project picked. A drop never moves the thread on its own.
  9. The dialog reuses the composer's parts: the project slot heading, the project chooser, and the target row.
